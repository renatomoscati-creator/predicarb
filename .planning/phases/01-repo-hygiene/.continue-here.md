## Phase 3: Benchmark Registry (BENCH-01..05) — after Phase 2

Create `src/benchmark/registry.py`. Design:
```python
from typing import Callable, Dict
from src.benchmark.csv_benchmark import BenchmarkProvider

BenchmarkFactory = Callable[..., BenchmarkProvider]
_REGISTRY: Dict[str, BenchmarkFactory] = {}

def register(name: str, factory: BenchmarkFactory) -> None:
    _REGISTRY[name] = factory

def build(name: str, **kwargs) -> BenchmarkProvider:
    if name not in _REGISTRY:
        raise ValueError(f"Unknown benchmark source: {name!r}. Available: {list(_REGISTRY)}")
    return _REGISTRY[name](**kwargs)
```

Register sources at module load time (in registry.py):
- `"constant"` → `ConstantBenchmark(prob=...)`
- `"zq"` → `ZqLiveBenchmark(meeting_date=..., ttl_seconds=...)`

Then `_build_benchmark()` in `src/cli.py` becomes a thin adapter that pulls from the registry.

Extend `run-multi` with same `--benchmark-source` / `--zq-meeting-date` / `--benchmark-ttl` flags as `run`.

## What this project is

PredicArb is a Polymarket edge-trading bot. The "edge" is `benchmark_prob − market_mid`. When that gap exceeds `min_edge`, it places a limit order. The benchmark is currently only ZQ futures (CME 30-Day Fed Funds Futures → implied P(cut at FOMC meeting)). The architecture is intentionally extensible via the `BenchmarkProvider` Protocol.

## Why this cleanup

The codebase was built fast across multiple sessions. It works and has good test coverage, but has accumulated dead code from a Kalshi→Polymarket migration that was never cleaned up, plus the project was never committed to git and has no packaging. The goal is to make it publishable and extensible (any financial source of truth as benchmark).

## Important API notes (don't re-learn these)

- Polymarket `GET /book?token_id=X` — orderbook. `timestamp` field is already milliseconds.
- `GET /price?token_id=X&side=buy` — best bid; `side=sell` — best ask.
- Gamma API `clobTokenIds` is a JSON string, needs `json.loads()` before indexing.
- ZQ futures: Yahoo Finance ~15min delay. `ZQ{code}{yy}.CBT` format.
- Late-month meetings (day ≥ 20): use NEXT month's ZQ as post-meeting reference.
